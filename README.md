# 수출적합성 판단 웹사이트

HS CODE(6단위) 입력 → 한국에서 각 국가로 수출할 때의 적합성 점수(0~100) 표시.
1인 작업 · 바이브코딩. AI는 작업 전 이 문서를 먼저 읽고 규칙을 따른다.

## 전제
- 수출국은 한국 고정
- 점수는 같은 HS CODE 내 국가 간 상대 점수
- 계산 단위는 HS 6단위

## 스택
Python · Flask(Jinja2) · pandas · SQLite · python-dotenv

## 디자인 (고정)
- 서체: Pretendard 단일
- 색상: 네이비/차콜 + 뉴트럴 그레이, 저채도. CSS 변수로만 사용
- 숫자: `font-variant-numeric: tabular-nums` 전역 적용, 표에서 우측 정렬

## 다국어
- 한/영 전환 (기본 ko), 세션 유지
- 문구는 `i18n/ko.json`, `en.json` 키로만 관리. 두 파일 키 동일 유지

## 규칙
1. 한 번에 한 기능만. 요청 외 기능·파일 추가 금지
2. 새 색상·라이브러리는 제안 후 승인
3. API 키는 `.env`에만
4. 외부 API 호출은 데이터 스크립트에서만. Flask는 DB 조회만

## 파일명
- 영문 소문자만. 한글·공백·대문자 금지
- Python·HTML·JSON: `snake_case` (예: `fetch_comtrade.py`, `score_result.html`)
- CSS·JS: `kebab-case` (예: `main.css`, `score-chart.js`)
- 역할이 드러나게. `final`, `new`, `test2`, `utils2` 같은 이름 금지
- 기존 파일 이름 변경·삭제는 먼저 묻기

## 수정하기 쉽게
- 바뀔 수 있는 값(가중치, 국가 목록, 기준연도 등)은 `config.py` 한 곳에 모은다. 코드에 숫자 직접 쓰지 않기
- 함수는 한 가지 일만. 길어지면 나눈다
- 이유가 필요한 코드에만 짧은 주석 (무엇이 아니라 왜)
- 수정은 관련 파일만. 무관한 코드 정리·리팩터링 금지
- 작업 후 변경한 파일 목록과 확인 방법을 짧게 보고
- 결정이 바뀌면 이 문서부터 수정
